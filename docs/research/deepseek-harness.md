# DeepSeek & Open-Model Coding Harnesses (deepseek-harness)

One-line description: The ecosystem of harnesses that run DeepSeek and other open/Chinese models (Qwen, Kimi, GLM) as coding agents — spanning DeepSeek's official Anthropic-compatible endpoint for Claude Code, community routing proxies, vendor-native CLIs, and Aider as the canonical open-model-first harness.

Researched: 2026-09-26

Scope note: unlike a single product, this subject is a *category*. The document covers (a) DeepSeek's official Claude Code compatibility, (b) community harnesses/proxies, (c) vendor-native open-model CLIs, (d) Aider as the reference open-model-first design, and (e) the failure modes and design deltas when the backend is a weaker/open model instead of Claude.

## 1. What it is

- **DeepSeek's Anthropic-compatible endpoint** — official DeepSeek API feature: `base_url = https://api.deepseek.com/anthropic` accepts the Anthropic Messages API, so Claude Code, the Anthropic SDK, and Claude Desktop dev mode can run on DeepSeek models by changing only env vars ([DeepSeek API docs](https://api-docs.deepseek.com/guides/anthropic_api)). Pay-per-token API pricing; DeepSeek V4-era models are mapped: `claude-opus*` → `deepseek-v4-pro`, `claude-haiku*`/`claude-sonnet*` → `deepseek-flash`. Unknown model names fall back to `deepseek-flash`.
- **Community harnesses** — proxies/routers that adapt Claude-Code-shaped traffic to open models: [musistudio/claude-code-router](https://github.com/musistudio/claude-code-router) (the dominant one; Node.js, local proxy with a React management UI, transformer/plugin system), litellm-as-proxy ([example](https://github.com/paoloanzn/free-code/issues/20)), OpenAI→Anthropic protocol bridges like [ClaudeZen](https://github.com/azurejoga/ClaudeZen), and Ollama's built-in Anthropic-compatible endpoint (`ollama launch claude --model kimi-k2.5:cloud`, [source](https://www.cnblogs.com/xgqfrms/p/19714304)). All free/open-source; distribution via npm/pip.
- **Vendor-native open-model CLIs** — [Qwen Code](https://www.morphllm.com/qwen-cli) (Alibaba; fork of Gemini CLI retuned for Qwen; ~18K GitHub stars; free Qwen OAuth tier), [Kimi Code CLI](https://www.marktechpost.com/2026/06/06/moonshot-ai-releases-kimi-code-cli-a-terminal-ai-coding-agent-built-in-typescript-for-next-gen-agents/) (Moonshot AI; TypeScript, MIT-licensed, defaults to Kimi models but model-agnostic), and Z.ai's [ZCode](https://venturebeat.com/technology/z-ai-launches-zcode-to-challenge-cursor-claude-code-and-github-copilot-in-ai-coding) plus the [GLM Coding Plan](https://docs.z.ai/devpack/overview) — a ~$18/mo flat subscription with an Anthropic-compatible endpoint that officially supports Claude Code, Cline, OpenCode ([GPUSmith summary](https://gpusmith.com/articles/en/pdfs/glm-5-2-hardware-requirements.pdf)).
- **Aider** — the canonical open-model-first harness: Apache-2.0 terminal pair-programmer by Paul Gauthier / Aider AI LLC, `pip install aider-chat`, connects to ~100+ LLMs (including local Ollama) via litellm, BYOK pay-per-use ([aider.chat](https://aider.chat/docs/usage.html), [FAQ](https://aider.chat/docs/faq.html)).
- Target users across the category: cost-sensitive developers (DeepSeek/Kimi tokens are ~10-30x cheaper than Claude), Chinese-market developers, privacy/offline users (local models), and tinkerers avoiding Anthropic subscriptions.

## 2. Core design philosophy

- **DeepSeek's stance**: meet the Claude ecosystem where it is. "To meet the demand for using the Anthropic API ecosystem, our API has added support for the Anthropic API format... With simple configuration, you can integrate the capabilities of DeepSeek into the Anthropic API ecosystem" ([DeepSeek docs](https://api-docs.deepseek.com/guides/anthropic_api)). The harness is treated as someone else's problem; the vendor ships protocol compatibility, not an agent loop.
- **claude-code-router's stance**: Claude Code is a great *client*; the model should be a pluggable, per-scenario choice. Route background/think/long-context requests to different models and providers, transform requests in flight, keep the Claude Code UX ([CCR overview](https://zread.ai/musistudio/claude-code-router/15-environment-variable-integration), [ClaudeLog](https://www.claudelog.com/claude-code-mcps/claude-code-router/)). Kimi sponsors the project and ships as a built-in provider preset ([DiscoverGit review](https://discovergit.app/repo/musistudio/claude-code-router)).
- **Aider's stance**: the harness must be *model-adaptive*, not model-agnostic in the naive sense. Aider ships per-model configurations for edit format, repo-map use, system-prompt placement, temperature, and token limits, and measures each model's edit-format compliance on its public leaderboard ([model settings docs](https://aider.chat/docs/config/adv-model-settings.html), [leaderboards](https://aider.chat/docs/leaderboards/)). Git is the safety net and the UX: every AI change is an auto-commit, so review/undo/diff are just git operations.
- **Vendor-CLI stance** (Qwen Code, Kimi Code CLI): fork or rebuild the proven agent UX around your own model rather than fighting protocol drift through a compatibility shim; Qwen Code explicitly forked Gemini CLI and retuned prompts/parsers for Qwen ([arcbjorn state-of-CLI-agents](https://blog.arcbjorn.com/state-of-cli-coding-agents-2026)).

## 3. Feature inventory

### 3.1 DeepSeek Anthropic endpoint (protocol surface, not a harness)

- Env-var integration: `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`, `ANTHROPIC_AUTH_TOKEN=$DEEPSEEK_API_KEY`, plus model vars; works in Claude Code CLI and IDE plugins ([setup guide](https://we0.ai/en/articles/claude-code-deepseek-setup-tutorial-anthropic)).
- Supported: `max_tokens`, `stop_sequences`, `stream`, `system`, `temperature` (0-2), `thinking` (**`budget_tokens` ignored**), `output_config.effort` only, tool definitions, `tool_choice` (none/auto/any/tool; **`disable_parallel_tool_use` ignored**), tool_use/tool_result blocks, images, server_tool_use/web_search results.
- Ignored: `anthropic-version`, `anthropic-beta` (except Files API), `top_k`, `container`, `mcp_servers`, all `cache_control` markers (no prompt-cache control exposed), `service_tier`, most `metadata`. `top_p` only effective in thinking mode (floor 0.95); fixed 1.0 otherwise.
- Not supported: `document` content blocks, `search_result`, `redacted_thinking`, `code_execution_tool_result`, `mcp_tool_use/result`, `container_upload` ([full compat table](https://api-docs.deepseek.com/guides/anthropic_api)).

### 3.2 claude-code-router (CCR) — the reference community harness

- Local proxy between Claude Code and any provider (OpenRouter, DeepSeek, Ollama, Gemini, Volcengine, SiliconFlow, Kimi built-in preset) ([DeepWiki](https://deepwiki.com/musistudio/claude-code-router/1-overview), [npm](https://www.npmjs.com/package/@musistudio/claude-code-router)).
- **Scenario-based routing**: different models for default/background/think/longContext/webSearch routes — the key insight that a coding session is several distinct workloads with different cost/quality needs.
- Transformer modules that rewrite requests/responses per provider (e.g., Anthropic tool schema → OpenAI function schema); plugin system for custom transformers; React web UI for config ([Zread architecture](https://zread.ai/musistudio/claude-code-router/3-configuration-guide)).
- CLI (`ccr`) plus optional desktop app with tray/notifications ([npm](https://www.npmjs.com/package/@musistudio/claude-code-router)).

### 3.3 Aider — feature inventory

- **Agent loop shape**: interactive chat REPL, not an autonomous tool-calling loop. The model emits *edits* in a declared format; aider parses, applies, lints/tests, and git-commits. File context is explicit: user `/add`s files; model can request more files and aider re-submits the original request after adding ([FAQ](https://aider.chat/docs/faq.html)).
- **Chat modes**: `code`, `ask`, `architect`, `help`; recommended ask→code planning workflow; per-message mode override via `/code`, `/ask` etc. ([modes doc](https://aider.chat/docs/usage/modes.html)).
- **Architect/editor mode**: main (architect) model proposes a solution in prose; a second "editor model" converts it into syntactically valid edit blocks. Exists because some models can reason but can't reliably emit edit syntax; default editor model chosen per main model.
- **Edit formats**: `whole` (rewrite file), `diff` (git-conflict-style SEARCH/REPLACE blocks), `diff-fenced` (path inside fence — for Gemini), `udiff` (simplified unified diff — for GPT-4-Turbo "lazy coding"), `editor-diff`/`editor-whole` (streamlined prompts for architect mode). Per-model defaults; force with `--edit-format` ([edit formats doc](https://aider.chat/docs/more/edit-formats.html)).
- **Repo map**: tree-sitter-extracted symbols/signatures for the whole repo, ranked by a graph algorithm over file dependencies (PageRank-style) to fit a token budget (`--map-tokens`, default 1k; expands when no files are in chat) ([repomap doc](https://aider.chat/docs/repomap.html)). **Disabled by default for weak models** — they get confused and try to edit the map ([FAQ](https://aider.chat/docs/faq.html)).
- **Per-model settings** (the crown jewel): YAML-configurable per model: `edit_format`, `weak_model_name`, `use_repo_map`, `reminder` (user vs sys placement), `examples_as_sys_msg`, `lazy`, `overeager`, `use_temperature`, `extra_params`, `cache_control`, `caches_by_default`, `editor_model_name`, `editor_edit_format`, `reasoning_tag`, `accepts_settings`. E.g. `deepseek/deepseek-reasoner` ships with `use_temperature: false`, `max_tokens: 64000`, editor = deepseek-chat; Kimi K2 with `temperature: 0.6` ([adv model settings](https://aider.chat/docs/config/adv-model-settings.html)).
- **Git-native UX**: auto-commit per change with attribution, `/undo`, diff display, "aider wrote N% of this release" stats via git-blame ([FAQ](https://aider.chat/docs/faq.html)).
- **Context tools**: `/add`, `/read` (read-only files, even from other repos), `/drop`, `/clear`, `/reset`, `/tokens`, `/run` (shell output into chat), `/map`, `.aiderignore`, `--subtree-only`, conventions/rules files (CONVENTIONS.md etc.).
- **Feedback loops**: auto-lint after edits, `/test` with auto-fix attempts, reflection loop when edits fail to apply (re-sends with error feedback).
- **Surfaces**: terminal REPL, `--browser` web UI, IDE integration (VS Code etc. via terminal/watch mode), scripting API (CLI + Python), voice-to-code, image/web-page input, shareable chat logs ([usage](https://aider.chat/docs/usage.html)).
- **No subagents, no MCP server management, no permission sandbox** — gaps vs Claude Code ([qwen-ai comparison](https://qwen-ai.com/2-5-coder/)).
- **Benchmarks as a feature**: the [polyglot leaderboard](https://aider.chat/docs/leaderboards/) scores % solved *and* % edit-format compliance per model — e.g. gpt-5 (high) 88.0% @ $29.08, DeepSeek-V3.2-Exp Reasoner 74.2% @ $1.30 (97.3% format compliance), Kimi K2 59.1% @ $1.24, Qwen3-235B 59.6%, gpt-4o-mini 3.6%. Note: the published leaderboard snapshot appears dated (mid-2025-era models); treat exact rankings as historical.

### 3.4 Vendor CLIs

- **Qwen Code**: Gemini CLI fork; subagents, plan mode, VS Code/Zed/JetBrains integration via ACP, free OAuth quota ([Morph guide](https://www.morphllm.com/qwen-cli), [arcbjorn](https://blog.arcbjorn.com/state-of-cli-coding-agents-2026)).
- **Kimi Code CLI**: single-binary/script install, fast TUI, video input (screen recording → code), MCP support, model-agnostic config, OAuth subscription or BYOK ([review](https://andrew.ooo/posts/kimi-code-cli-review-moonshot-terminal-agent/), [MarkTechPost](https://www.marktechpost.com/2026/06/06/moonshot-ai-releases-kimi-code-cli-a-terminal-ai-coding-agent-built-in-typescript-for-next-gen-agents/)).
- **Z.ai GLM Coding Plan**: flat-rate subscription (~$18/mo tier) usable *inside third-party harnesses* (Claude Code, Cline, OpenCode, OpenClaw) via Anthropic-compatible endpoint; GLM-5.2 offers 1M-context variant and 128K output ([docs](https://docs.z.ai/devpack/overview), [The Decoder](https://the-decoder.com/zhipu-ais-glm-5-2-closes-in-on-closed-source-leaders-in-coding-marathons/)).

## 4. Architecture

- **DeepSeek endpoint**: server-side protocol adapter; model-name aliasing layer maps `claude-*` names to DeepSeek models; unsupported fields silently ignored rather than rejected (mostly), which papers over but also hides capability gaps ([docs](https://api-docs.deepseek.com/guides/anthropic_api)).
- **CCR**: Node.js local HTTP proxy; pipeline = router engine → transformer chain (per-provider request/response adapters) → provider; React UI writes a JSON config; agent sub-framework for special cases like image handling ([Zread](https://zread.ai/musistudio/claude-code-router/3-configuration-guide)).
- **Aider**: Python, single local process. litellm abstracts 100+ providers; model metadata (context size, cost) pulled from litellm's `model_prices_and_context_window.json`, overridable via `.aider.model.metadata.json`. Modular "coder" classes pair a system-prompt module with an edit-format parser (`aider/coders/*_coder.py` + `*_prompts.py`) — new models get a new pairing, not a fork ([FAQ](https://aider.chat/docs/faq.html)). Repo map built with tree-sitter tags + networkx graph ranking; token budget enforced via greedy selection. All persistence via git; chat history in `.aider.chat.history.md`.
- **Qwen Code**: TypeScript fork of Gemini CLI codebase with Qwen-specific prompts, parsers, and OAuth; **Kimi Code CLI**: TypeScript, standalone runtime ([MarkTechPost](https://www.marktechpost.com/2026/06/06/moonshot-ai-releases-kimi-code-cli-a-terminal-ai-coding-agent-built-in-typescript-for-next-gen-agents/)).

## 5. Strengths (community-cited)

- **Cost is the killer feature.** DeepSeek on aider's leaderboard: 74.2% solve rate for $1.30/run vs $29-65 for frontier models ([leaderboard](https://aider.chat/docs/leaderboards/)); "Aider + Gemini Flash or DeepSeek runs at 1/10th the cost" is a recurring Reddit budget stack; aider reportedly uses ~4.2x fewer tokens than Claude Code on the same tasks ([CodeMySpec](https://codemyspec.com/blog/open-source-vs-vendor-locked-ai-coding-tools)).
- **Drop-in simplicity of the DeepSeek endpoint**: "you do not need to change how you use Claude Code. You only need to change environment variables" ([we0.ai guide](https://we0.ai/en/articles/claude-code-deepseek-setup-tutorial-anthropic)); bundled launchers exist ([ozp3/claude-code-deepseek](https://github.com/ozp3/claude-code-deepseek)).
- **Aider's git-native review loop** is the most-praised property: "git integration built-in" / "edits files directly" vs copy-paste tools; easy diff/undo ([Reddit roundup](https://www.aitooldiscovery.com/guides/best-ai-for-coding-reddit), [vibecodinghub review](https://vibecodinghub.org/tools/aider)).
- **No lock-in**: swap providers when pricing/quality shifts without changing tools ([Kunal Ganglani comparison](https://www.kunalganglani.com/blog/aider-vs-claude-code)).
- **Kimi K2-class models genuinely work in Claude Code** for routine work; "How I'm using Kimi K2 in Claude Code" guides proliferated ([r/vibecoding](https://www.reddit.com/r/vibecoding/comments/1lzss0c/how_im_using_kimi_k2_in_claude_code/)).
- **GLM Coding Plan economics**: flat ~$18/mo subscription that works inside Claude Code is repeatedly cited as the cheapest way to get a Claude-Code-shaped workflow ([Z.ai docs](https://docs.z.ai/guides/overview/quick-start), [VentureBeat](https://venturebeat.com/technology/z-ai-launches-zcode-to-challenge-cursor-claude-code-and-github-copilot-in-ai-coding)).
- HN sentiment: "There is Aider, and it has been there for a couple years now. Great tool." ([HN](https://news.ycombinator.com/item?id=46060508)).

## 6. Weaknesses (community-cited)

- **Protocol drift breaks the drop-in promise.** Claude Code v2.1.154+ sends mid-conversation `role: "system"` messages; Qwen's and DeepSeek's Anthropic endpoints reject them (`messages[1].role: unknown variant 'system'`) — workaround is downgrading Claude Code or adding a rewriting proxy ([QwenLM/Qwen#2244](https://github.com/QwenLM/Qwen/issues/2244)). Kimi's endpoint rejects `document` content blocks (PDF workflows 400 out) ([Kimi-K2.5#27](https://github.com/MoonshotAI/Kimi-K2.5/issues/27)). Claude Code Agent/subagent spawns 400-fail on DeepSeek's endpoint (`thinking options type cannot be disabled when reasoning_effort is set`) while the main conversation works — subagents silently unusable for days in one report ([claude-code#65863](https://claudeissues.com/issue/65863-claude-code-v2-1-167-agent-spawn-fails-with-400-thinking-options-type-cannot-be)). Kimi-in-Claude-Code setup hits model-mapping, missing-`max_tokens`, and `tool_choice` errors ([CSDN walkthrough](https://blog.csdn.net/2601_95893623/article/details/162240647)).
- **Tool-calling reliability gap is model-level, not prompt-fixable.** A 29-case agent eval (authored by Claude Opus 4.6, human-reviewed) scored DeepSeek V3 at 81.5% vs Qwen Plus 96.5%: DeepSeek distrusts tool results and retries 5-10 rounds, has weak Windows cmd knowledge, and spirals on GBK encoding; "I tested multiple prompt variations with no improvement" ([DeepSeek-V3#1108](https://github.com/deepseek-ai/DeepSeek-V3/issues/1108)). Independent academic work: open-source models lag closed ones under noisy tool settings; tool-finetuned open models can score <10% despite high BFCL ([EMNLP 2025 findings](https://aclanthology.org/2025.findings-emnlp.1344.pdf)).
- **Context-length mismatch.** Harnesses tuned for Claude's 200K/1M window inject huge prompts; older DeepSeek deployments were 64K, where "the model gets really slow... and attention degrades quickly" ([HN](https://news.ycombinator.com/item?id=48047836)); Cline misreported DeepSeek's window as 64K ([cline#4368](https://github.com/cline/cline/issues/4368)). A third-party "context-optimizer for DeepSeek's 64k window" skill exists purely to compensate ([cmdop](https://cmdop.com/zh/skills/context-optimizer-1/)).
- **Weak models drown in context.** Aider disables the repo map by default for weak models because they "get easily overwhelmed and confused... and mistakenly try to edit the code in the repo map"; the FAQ urges adding *fewer* files because extra context degrades results ([aider FAQ](https://aider.chat/docs/faq.html)).
- **Edit-format fragility.** Gemini needed a special `diff-fenced` format; GPT-4-Turbo needed `udiff` to suppress "lazy" elision; leaderboard compliance rates vary wildly (gpt-5 diff: 91.6%; chatgpt-4o-latest: 64.4%) — the same model+prompt can lose a third of its edits to parse failures ([leaderboard](https://aider.chat/docs/leaderboards/), [edit formats](https://aider.chat/docs/more/edit-formats.html)).
- **Aider's own gaps**: no subagents/MCP/sandbox; user must curate file context (skill barrier); not optimized for huge monorepos; chat-first loop means more human round-trips than autonomous agents ([qwen-ai](https://qwen-ai.com/2-5-coder/), [HN on Plandex comparison](https://www.supertechfans.com/cn/post/2024-04-12-HackerNews/)).
- **BYOK economics cut both ways**: HN notes agentic coding "only makes sense through subscription billing" — a day of heavy API use can exceed a $200/mo plan, which is precisely what Z.ai/Moonshot exploit with flat-rate plans ([HN](https://news.ycombinator.com/item?id=46060508)).

## 7. Distinctive ideas worth borrowing

1. **Per-model capability profile, not per-model if-statements.** Aider encodes each model as data: edit format, whether repo map helps or hurts, system-prompt placement, temperature, editor-model pairing, max output tokens, reasoning tag. Adding a model = adding a YAML record ([settings doc](https://aider.chat/docs/config/adv-model-settings.html)). A new agent should make this a first-class, user-overridable registry — ideally with per-model benchmark-derived defaults.
2. **Edit format as a benchmarked contract.** Don't assume one edit syntax. Ship whole-file, search/replace, and unified-diff formats; measure each model's *format compliance rate* separately from task success; let per-model config pick the format. Weak models often do better with the dumbest format (whole file); frontier models save 10x tokens with diffs.
3. **Architect/editor split.** Two cheap calls can beat one expensive one: a reasoning-strong model proposes changes in prose; an editor model (or the same model with a narrower prompt) emits machine-parseable edits. This rescues models that are smart but syntactically unreliable, and lets you mix vendors per role ([modes doc](https://aider.chat/docs/usage/modes.html)).
4. **Scenario-based routing (CCR).** A coding session is multiple workloads — main loop, background tasks, deep-thinking requests, long-context reads. Route each to the cheapest model that handles it; CCR makes this a config matrix. New agents should treat "which model" as a per-request decision, not a session global.
5. **Graph-ranked repo map with a token budget.** tree-sitter symbols → dependency graph → PageRank-style selection of the most-referenced definitions that fit ~1k tokens. Cheaper and more robust than embedding RAG for code, and degrades gracefully as the budget shrinks ([repomap](https://aider.chat/docs/repomap.html)). Crucially: *disable it for models that can't handle it* — context injection is model-dependent.
6. **Git as the safety, review, and undo layer.** Auto-commit every AI change with attribution; undo = `git revert`; stats = `git blame`. Zero new UX to learn, works offline, auditable. Far simpler than checkpoint systems — at the cost of requiring a git repo.
7. **Graceful protocol degradation.** DeepSeek's endpoint *ignores* unsupported fields (cache_control, top_k) rather than erroring — mostly right, though silent ignoring of `budget_tokens`/`disable_parallel_tool_use` can mislead. A new harness should explicitly normalize: rewrite mid-conversation system messages, strip document blocks the backend rejects, clamp max_tokens — and log every downgrade.

## 8. Lessons for a new agent

- **Don't trust "Anthropic-compatible" as a binary.** Compatibility is a long tail: role schemas, content-block types, thinking parameters, tool_choice, max_tokens requirements. Build a normalization/probe layer that tests the endpoint at startup (canary requests) and adapts, rather than assuming spec compliance.
- **Model swaps fail at the seams, not the center.** Main-conversation chat worked fine in every reported Claude Code→DeepSeek/Kimi case; what broke was subagents, PDFs, web tools, thinking params. Test the *whole tool surface* per backend, and feature-detect instead of version-detecting.
- **Budget for the model you have, not the model you wish you had.** Compaction triggers, system-prompt size, repo-map size, and subagent fan-out must scale with the actual usable context and tool-calling reliability of the configured model. Ship conservative defaults for unknown/weak models (small map, whole-file edits, no parallel tools, short loops).
- **Measure format compliance, not just task success.** A model losing 30% of edits to parse failures looks identical to a dumb model in end-to-end benchmarks. Compliance metrics per model+format let the harness pick formats empirically and give users trustworthy model recommendations.
- **Trust calibration is a model property; the harness must defend against it.** Open models retry tool calls they shouldn't and loop on benign errors. Add repeat-detection, round limits, and error-result summarization in the loop itself — prompting won't fix it ([DeepSeek-V3#1108](https://github.com/deepseek-ai/DeepSeek-V3/issues/1108)).
- **Own the UX if you own the model.** Qwen Code (fork) and Kimi Code CLI (rebuild) outpace shim approaches because prompts, parsers, and defaults can be co-designed with the model. If you're model-agnostic, invest in the per-model config registry instead.
- **Copy from aider**: git-native commits/undo, explicit file context with `/add`, repo map, architect/editor mode, model settings registry, public per-model benchmarks. **Avoid**: requiring users to hand-curate context (add agentic file discovery), no sandbox for shell commands, and ignoring MCP/subagents (table stakes by 2026).
- **The subscription-vs-BYOK tension is real**: power users on pay-per-token get burned; vendors win with flat plans. A new open-model harness should surface live cost per session and support budget caps — and consider routing to cheap models aggressively by default.
