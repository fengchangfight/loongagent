# 有限工作内存，无限对话

- **Date:** 2026-11-07
- **Status:** 目标与四条取舍已在对话中由 owner 确认（永不因上下文失败 / 忘记可重查 / 重查不必问 / 靠线索快速找回）；本文是可写实现计划的设计稿，待批准
- **Scope:** 把"上下文出问题"从**致命错误**改成**降级阶梯**；把"旧消息只能清不能移"改成"移出但留地址"；把"重查两跳"降到一跳。不改 JSONL 真相源，不引入重要性评分模型，不做子 agent 上下文隔离。

## 1. 问题

长会话会让任务**失败**，而不是变糙。`kkuj2j9t` 这个会话给出了完整证据：80 次压缩、最后 12 次都撞在上限（82,783→82,785 这种 0% 释放也算一次），第 31 步被 `compaction thrash` 刹停；其中一次请求 `tokens_in 107,099 / cache_hit 4,864`，等于付了全额价钱换了 0 收益。

更根本的是**取舍规则错了**。`Ledger` 的压缩只按年龄排序：先清最旧的工具输出，再丢最老的整轮对话。年龄是唯一维度，"这条是不是任务本身"不参与排序。于是被压掉的东西里可能有原始目标、用户明说过的约束、已否决的方案——它们和"某个文件第 37 行是什么"一起排队。任务失败不是因为上下文变短，是因为**变短时把任务一起压掉了，而且压掉之后没有回头路**。

四条硬停点，其中一条是真崩溃：

| 停点 | 现在 | 后果 |
|---|---|---|
| 供应商拒收（context length 超限） | `loop.rs` 的 `.map_err(KernelError::Model)?` | **整轮报错退出**，无补救；`budget_tokens` 未声明时根本不压缩 |
| 压缩空转 | `compaction_thrash()` 刹停 | 已经改成不误伤，但结局仍是"停" |
| 步数上限 | 返回"reply to continue" | 任务被切成两半，靠人续 |
| 停滞守卫 | 重复调用/连续失败就停 | **这条是对的**，不该动 |

## 2. 目标与非目标

**目标**

1. 上下文的任何问题都不导致任务失败。只能表现为：回答变短、细节靠重查、用户看到"正在降级"。
2. 忘记了就自己重查，**不问用户**要不要查。
3. 重查要便宜：一跳、有线索、找得到。
4. 重查回来的内容**本身还能再被移出**，否则"能重查"会变成"更快撑爆"。
5. 稳态下前置上下文不随对话长度单调增长。

**非目标**

- 不做"重要性评分"。判断哪条以后有用，一定会判断错，而且错了没有兜底。本设计**故意不做这个判断**。
- 不丢原文，不改 JSONL 真相源。
- 不做子 agent 独立上下文（另一件事）。

## 3. 核心判断：不追求"丢得准"，追求"找得回"

owner 的原话是：以前聊过的结论不记得了，那就从最原始的资料重新分析一遍，这不不合理。

这句话让设计重心转移，而且转移得对。**一切都已经在 JSONL 里**，所以"能不能找回"永远不是问题。真正决定成败的是三笔成本：

| 成本 | 现在的问题 | 对应手段 |
|---|---|---|
| **认知成本**：模型知不知道自己忘了东西、去哪儿查 | 清掉的输出只留一句"re-run the command"，没有任何地址 | 存根带 `seq` 区间 + 线索；L4 地图常驻（"有什么、在哪"） |
| **步数成本**：找回要几跳 | `recall` 拿到 id，再 `expand` 才见原文，两跳 | 压缩成一跳 |
| **上下文成本**：找回后又占了地方 | 展开的原文和普通消息一样只增不减 | 检索结果同样可被压回存根 |

推论：**取舍规则可以很粗**。因为要保的只剩下"地址还在、线索够用"，所以"按年龄 + 可再取回"就够了，不需要精确判断重要性。这也是人脑的实际做法——靠"谁、哪儿、什么时候"这类线索 + 快速重述，而不是先把每件事标好重要度再决定存哪。

## 4. 三档驻留

前台（发给模型的消息数组）按驻留强度分三档：

**A 常驻，永不压缩。** 两块，都很小：

1. **任务卡（`TaskCard`，新，pinned，≤ 800 tokens）**：当前目标、用户明说过的约束与否决（"不要动 X"）、正在验的假设、待办。
   只放**意志**，不放**推导结论**：结论可以重推，而一句"不要引入新依赖"被压成摘要就永久消失了，重推也推不出来——它是人的偏好，不是从资料里能算出来的东西。
2. **L4 记忆地图（已有，`Category::CognitiveMap`，pinned）**：有什么模块、有哪些已闭合的任务、各自的 `ep` 区间。这是"蛛丝马迹"的来源。

**B 近期原样。** 最近 K 轮的完整消息，逐字保留。

**C 存根（`Stub`，新）。** 更早的一切压成一行，仍然参与排序，仍然可再压缩。

A 档的实现复用现有 pinned 机制（`Entry.pinned`，淘汰时永不选中），不新建一套。

## 5. 降级阶梯：每格都继续干活

从轻到重，每次失败只降一格，降完**继续**，不抛错。这是"永远聊得下去"的全部机制。

| 格 | 动作 | 是否花钱 | 触发条件 |
|---|---|---|---|
| L0 | 清旧工具输出（现有 `clear_tool_outputs`） | 否（确定性） | 超过 aging 线 |
| L1 | 旧消息 → 存根 | 否（确定性抽提：工具名、成败、路径、`seq`） | 超过上限，L0 不够 |
| L2 | 相邻存根并段，线索取并集 | 否 | 存根仍太多 |
| L3 | **供应商拒收 → 识别为信号**，先降级再重试，同一轮内 | 否 | provider 返回 context-length |
| L4 | 最小可行请求：任务卡 + 最近一轮 + 地图，重试一次 | 否 | L3 后仍被拒 |
| L5 | 告知"这一轮我发不出去了"，**保住已有进度**，可续 | 否 | L4 仍被拒 |

两个要点：

- **降级本身绝不调用模型。** 摘要若靠模型做，就会在"上下文最紧张、用户正在等"的时刻排队等一次推理——那正是 ADR-0017 反对的形态。模型摘要只留在已有的空闲窗口 worker 里做，降级走确定性抽提。
- **L5 是唯一的"停"，而且不是失败**：明确说清原因，已完成的工作和日志都在，下一句就能接着做。这与现在的报错退出是两件事。

**步数上限**改为自动续期：一轮用尽预算后自动开下一段并把已完成的收进任务卡，连续 N 段没有进展才停（无进展的判据复用停滞守卫）。人不需要敲"continue"。

## 6. 存根的形态

一行，固定字段，模型一眼能判断"值不值得查"：

```
[ep-00000118-00000143] 修复 config 层叠失效（7 步，完成）
  改动: src/config/merge.rs, src/config/layer.rs | 验证: cargo test -p loong-config 通过
  线索: layer merge 优先级 环境变量 | 原文: recall seq 118-143
```

必须有的三样：**区间**（能取回）、**线索词**（用户原话里的词优先，否则模型按自己的话查会查不到）、**取回指令**（把"怎么查"直接写给它，省一次猜）。

失败的存根同样保留，并且标明失败——被否决的方案是最不该消失的信息，而它恰恰不是重跑命令能再生出来的。

## 7. 重查

- **一跳**：`recall {query}` 直接返回命中的**原文片段**（现在只返回摘要 id，需要第二次 `expand`）。`expand` 保留给"我要全文"的情况。
- **自主**：系统提示加一条纪律——回答过去的事之前先查；不确定就先查，**不要猜，也不要问用户要不要查**。
- **可再移出**：检索结果作为普通 `tool.result` 进入历史，因此也落在 C 档，能被压回存根。它天生带 `seq`，所以压回去之后还能再查。这条让"重查"不会引起上下文回升，闭环才成立。
- **防抖**：同一段被重查超过 N 次，说明它其实很重要——提升为 B 档原样保留。这是本设计里唯一允许的"重要性判断"，且由**实际使用**证明，而不是事先猜。

### 7.1 换个词也要查得到

"忘了就重查"只有在**换一种说法也能查到**时才成立。现状不是这样，而且 `semantic` 模式并没有解决它：

| 事实 | 位置 |
|---|---|
| 匹配是 `LIKE %词%`，多个词之间**隐式 AND** | `crates/context/src/summaries.rs:965`、`store.rs:902` |
| 排序只有 `ORDER BY seq_to DESC`（最新优先），没有相关性打分 | `summaries.rs:984` |
| 中文不分词：只按空白与标点切，无空格短语必须**整串连续**命中 | `crates/kernel/src/turn/recall.rs:171` |
| 没有任何向量 / embedding 基础设施 | 全仓无 vector 列、无 embedder |
| `semantic` 模式只让后台模型**补写 L2 摘要的语义字段**，不改变匹配方式 | `crates/kernel/src/context_engine.rs:1065` |

所以说 `semantic` 有帮助是对的——补写后的摘要含有模型自己的措辞，**碰巧**用词接近就能命中——但那只是提高了撞词的概率，机制没变：一个词不对，整条查询返回零。

据此分三层，从免费到收费：

**第一层（确定性，零成本，立刻见效）：OR + 相关性排序。**
任一 term 命中即可返回，按"命中的不同词数"排序，同分再按新旧。这一层单独就修掉最痛的一半——现在的问题不是"没匹配到"，而是一个词对不上就把整条查询清零。返回值仍受条数与字符上限约束。

**第二层（复用已有 semantic 模式，重查时零成本）：摘要带别名。**
后台小模型富化 L2 摘要时，**额外**产出一组 `aliases`（同义说法、中英对照、模块名、用户原话里的词），存进带索引的列；`recall` 匹配 title/content/aliases，别名命中权重略低。这是"开启 semantic 后换词能查到"的**正确兑现方式**：成本发生在空闲窗口，重查时只是一次 SQL。诚实的边界：只覆盖已被富化过的段落；`record` 模式下这一层不存在，第一层仍然有效。

**第三层（不做）。** 查询扩展要在重查时再问一次模型，而重查正是延迟敏感路径。owner 的判断是："把摘要写得更丰富、撞词概率高一点就够了，不需要 perfect，因为 perfect 的代价太 heavy。" 所以这一层不实现：零结果就如实回答零结果，让模型换个词再试——它自己就会。

**第一、二层不动摇的边界：** 别名只提高命中率，不改变"命中的是摘要、原文仍要靠 `expand`"这一事实。别名永远不能成为记忆本身。

**明确不做：本阶段不引入 embedding。** 理由：多一个模型依赖、多一类失败模式，而第二层用现成设施能拿到大部分收益。这一条是可以被推翻的取舍，写在 §9。

## 8. 可见性

降级发生时：状态行显示（如 `ctx 92% ↓stub`），模型自己也看得到（存根里写明细节可 `recall`）。**不静默降质**：质量下降是允许的，隐瞒不是。

## 9. 风险与取舍（我做主的几处，可逐条否决）

| 判断 | 我的理由 | 如果错了会怎样 |
|---|---|---|
| 任务卡 ≤ 800 tokens 硬上限 | 常驻层挤占的是所有轮次的空间，必须封顶 | 上限太小 → 目标和约束装不下；需要按超限合并规则处理 |
| 降级不调用模型 | 降级时刻是延迟最敏感的时刻 | 确定性抽提的存根偏机械、可读性差，但线索字段仍然完整 |
| 一跳返回原文片段 | 省一轮往返，这是"重查便宜"的关键 | 返回变长，用硬字符上限 + 截断标注兜住 |
| 步数上限改自动续期 | owner 明确不想被打断 | 可能掩盖真死循环；用停滞守卫 + 无进展判据兜底 |
| 不做重要性评分 | 判断会错且无兜底 | 有些该留的被压成存根，代价是多一次重查 |
| **不引入 embedding，先用 OR 排序 + 摘要别名** | 多一个模型依赖与失败模式；现成设施能拿到大部分收益 | 真同义（"超时"vs"卡住"）仍查不到，只能靠模型换个词再试 |
| **不做查询扩展**（owner 决定） | 重查是延迟敏感路径；"够用"比 perfect 便宜得多 | 首次查询的换词能力弱于全程语义检索，偶尔要模型重试两次 |
| 别名由富化时的后台模型产出，不由重查时现算 | 重查是延迟敏感路径；空闲窗口才是花模型的时间 | 未被富化的段落没有别名，只能靠第一层的 OR 匹配 |
| 别名存进 `content` 的尾部一行，不加列 | 加列要升 `SCHEMA_VERSION`，而版本不匹配是**打开失败**，旧会话会直接失去记忆 | 别名会占几十 token；用渲染时跳过该行的办法兜住 |

## 10. 验收（先写成测试，再写实现）

1. 一个 100 步、每步大输出的会话**跑完**，日志里不出现任何 stop/failure 事件。
2. 供应商返回 context-length 错误时，同一轮**降级后成功**（现在会整轮失败）。
3. `recall {query}` **一次调用**就带出原文片段（现在要两次）。
4. 检索结果被压回存根后**仍能再查出**（幂等）。
5. 一段前置上下文（不含工具输出）在 50 轮后**不再增长**（稳态平坦）。
6. 任务卡超限时**被合并而不是被挤出**（pinned 永不被淘汰，所以溢出必须显式处理）。
7. **换词查得到**：一段记录里写的是"配置合并优先级"，用"层叠"查仍能命中（第一层 OR 排序 + 第二层别名）。
8. **一个错词不清零**：`"层叠 某个根本不存在的词"` 仍返回含"层叠"的记录，而不是空结果。
9. 别名命中不越过原文：别名只能定位到摘要，`expand` 仍然强制给出原文事件。
10. `cargo test -p loong-kernel -p loong-context` 与 `./scripts/check.sh` 全绿。
