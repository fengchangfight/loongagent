# Pi (pi-mono) — the minimal, self-extensible coding agent harness

> One-liner: A deliberately minimal, MIT-licensed TypeScript coding-agent harness — four tools, a ~1k-token system prompt, no MCP/subagents/permissions in core — built by Mario Zechner ("badlogic", libGDX creator) so that users extend the agent instead of adapting to it.

**Researched: 2026-09-26**

Primary sources: [origin blog post "What I learned building an opinionated and minimal coding agent" (2025-11-30)](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/), [pi.dev](https://pi.dev) / [docs](https://pi.dev/docs), [GitHub repo (badlogic/pi-mono → earendil-works/pi)](https://github.com/badlogic/pi-mono), ["I've sold out" (Earendil announcement, 2026-04-08)](https://mariozechner.at/posts/2026-04-08-ive-sold-out/), [Mastra talk summary "I Hated Every Coding Agent, So I Built My Own" (2026-03-31)](https://with-agents.dev/summaries/coding-with-agents/i-hated-every-coding-agent-so-i-built-my-own-mario-zechner-pi/), [developersdigest deep dive (2026-08-23)](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture), [heyuan110 hands-on review (2026-09-06)](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/), [Alex Dunlop: Pi vs Claude Code (2026-08-06)](https://www.alexdunlop.com/writing/pi-vs-claude-code-which-ai-coding-agent-in-2026).

## 1. What it is

- **Maker**: Mario Zechner ([@badlogic](https://github.com/badlogic)), creator of libGDX (the dominant Android game framework of the early 2010s). Started as a personal protest harness in repo `badlogic/pi-mono` (created 2025-08-09; founding blog post 2025-11-30). In April 2026 he joined **Earendil** (Armin Ronacher's company) taking Pi with him; the repo moved to `earendil-works/pi` and packages to the `@earendil-works` npm scope ([I've sold out](https://mariozechner.at/posts/2026-04-08-ive-sold-out/)).
- **Target users**: power users and agent *builders* — people who want to own their harness, do context engineering, embed an agent in products (SDK/RPC), or run non-Anthropic models. OpenClaw (Peter Steinberger's agent) is built on Pi packages; `pi-tui` alone reportedly sees ~5M npm downloads/week, more than the CLI itself, i.e. Pi is as much infrastructure as product ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **Surfaces**: terminal-first. One agent core, four run modes: interactive TUI, print/JSON headless (`pi -p`, `--mode json`), RPC over stdin/stdout JSONL (for non-Node clients; an Emacs mode exists), and an embeddable TypeScript SDK (`createAgentSession`). No official IDE plugin, desktop app, or cloud service; third parties build those on RPC/SDK ([pi.dev](https://pi.dev)).
- **Pricing/distribution**: MIT-licensed, free; you pay the model provider. Installed via `npm install -g @earendil-works/pi-coding-agent` or a curl installer; standalone binaries on GitHub releases. Announced future commercialization: three tiers — MIT core "forever, non-negotiable", Fair Source value-add features (delayed open source), proprietary enterprise/cloud (not yet built as of the announcement). Trademark, not license, is the protection mechanism ([I've sold out](https://mariozechner.at/posts/2026-04-08-ive-sold-out/)).
- **Scale** (secondary sources, verify live): ~95.9k stars / 11.9k forks on 2026-08-23 ([developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)); ~103.9k stars, CLI at v0.85.1 with ~1.5M weekly npm downloads on 2026-09-06 ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)). ~255 tagged releases since 2025-12 — roughly a release a day, still pre-1.0.
- Name origin: deliberately "entirely un-Google-able" so it would never attract users or issues — "There are many shitty coding agents, but this one is mine" (original site shittycodingagent.ai, now pi.dev) ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

## 2. Core design philosophy

- **"If I don't need it, it won't be built. And I don't need a lot of things."** ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/))
- **"Adapt Pi to your workflows, not the other way around"** — the README/manifesto line. Pi is "a minimal agent harness… Pi ships with powerful defaults but skips features like sub-agents and plan mode. Ask Pi to build what you want, or install a package that does it your way" ([pi.dev](https://pi.dev)).
- **Anti-spaceship**: Claude Code "turned into a spaceship with 80% of functionality I have no use for. The system prompt and tools also change on every release, which breaks my workflows and changes model behavior. I hate that." ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/))
- **Context engineering is paramount**: "Exactly controlling what goes into the model's context yields better outputs… Existing harnesses make this extremely hard or impossible by injecting stuff behind your back that isn't even surfaced in the UI." Pi's promise: nothing hidden, everything inspectable, documented session format.
- **Models don't need much harness**: frontier models are "RL-trained up the wazoo, so they inherently understand what a coding agent is. There does not appear to be a need for 10,000 tokens of system prompt." Evidence cited: Terminus on Terminal-Bench performs strongly with little more than tmux + keystrokes; Pi itself scored near the top of Terminal-Bench 2.0 with Claude Opus 4.5 *before Pi even had compaction* ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/), [talk summary](https://with-agents.dev/summaries/coding-with-agents/i-hated-every-coding-agent-so-i-built-my-own-mario-zechner-pi/)).
- **Nobody knows the right shape yet, so the harness must be cheap to change**: "The field is still experimenting… harnesses should be easy to change." Developers and agents should modify the surrounding software instead of waiting for vendors ([talk summary](https://with-agents.dev/summaries/coding-with-agents/i-hated-every-coding-agent-so-i-built-my-own-mario-zechner-pi/)).
- **The explicit refusals** (verbatim from the README's Philosophy section, via [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)):
  > "No MCP. Build CLI tools with READMEs, or build an extension that adds MCP support."
  > "No sub-agents. Spawn pi instances via tmux, or build your own with extensions…"
  > "No permission popups. Run in a container, or build your own confirmation flow with extensions…"
  > "No plan mode. Write plans to files…"
  > "No built-in to-dos. They confuse models. Use a TODO.md file…"
  > "No background bash. Use tmux. Full observability, direct interaction."
- **On security**: permission systems in agents are "mostly security theater. As soon as your agent can write code and run code, it's pretty much game over… Everybody is running in YOLO mode anyways to get any productive work done, so why not make it the default and only option?" (citing Simon Willison's lethal-trifecta writings) ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

## 3. Feature inventory

**Agent loop shape**
- `pi-agent-core`: loop executes tool calls, feeds results back, repeats "until the agent says it's done" — deliberately no max-steps knob. `Agent` class adds state management, event subscriptions, message queuing, attachment handling, transport abstraction (run directly or via proxy) ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).
- **Steer vs follow-up queue**: while the agent works, `Enter` queues a *steering* message (delivered after the current tool call, interrupts remaining tools); `Alt+Enter` queues a *follow-up* (delivered when all work completes) ([pi.dev](https://pi.dev)).

**Tools the agent has**
- Exactly four by default: `read` (text + images, offset/limit paging), `write` (create/overwrite, makes parent dirs), `edit` (exact-match string replacement), `bash` (synchronous, optional timeout). No grep/find/ls tools — "Use bash for file operations like ls, grep, find" per the system prompt.
- Optional read-only companions (`grep`, `find`, `ls`) can be enabled for restricted runs, e.g. `pi --tools read,grep,find,ls` gives a read-only exploration mode.
- No web search/fetch tool by default (curl via bash is the assumed path). No background bash; tmux is the prescribed answer (full observability, human can co-debug in the same tmux session).
- Tool results are **structured and split**: one content payload for the LLM, a separate `details` payload for UI rendering; tools can return images natively. Args validated via TypeBox + AJV. Partial JSON parsing streams tool-call args into the UI (e.g. diffs render as they stream) ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

**Context management**
- **System prompt**: ~14 lines, system prompt + tool definitions measured at <1,000 tokens (origin) / 1,358 tokens minimal footprint measured by [heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/) vs 31,012 for Claude Code in the same test. The prompt even points the model at its own README so it can configure itself.
- **AGENTS.md**: loaded hierarchically (global `~/.pi/agent/`, parent dirs, project dir). **SYSTEM.md**: replace or append to the system prompt per project.
- **Compaction**: auto-triggers when `contextTokens > contextWindow - reserveTokens` (16,384 reserve default); keeps the newest ~20k tokens verbatim, summarizes the rest with a structured template (goal, constraints, progress, decisions, next steps, files read/modified). Cut points never split a tool call from its result; repeated compactions re-summarize from the previous boundary; the full history survives in the JSONL file. Fully replaceable via the `session_before_compact` extension hook ([developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)).
- **Skills**: Anthropic-style Agent Skills (instructions + resources, progressive disclosure, cache-friendly), auto-discovered from `~/.agents/skills` and `.agents/skills`.
- **Prompt templates**: markdown files expanded as `/name` slash commands.
- **No built-in to-dos or plan mode**: prescribed alternatives are `TODO.md` / `PLAN.md` files the agent reads and updates — externally stateful, versionable, observable. Rationale: to-do tools "confuse models more than they help"; planning needs observability that black-box plan modes don't give ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

**Sessions**
- **Tree-structured sessions in a single JSONL file** at `~/.pi/agent/sessions/--<path>--/<timestamp>_<uuid>.jsonl`; every entry has `id` + `parentId`. Entry types include messages, `model_change`, `thinking_level_change`, `compaction`, `branch_summary`, labels/bookmarks, and extension-defined custom entries.
- `/tree` navigates the whole tree and continues from any point; `/fork` copies the active branch into a new session file; `/clone` duplicates the branch. Jumping branches can auto-generate a `branch_summary` of the abandoned path. `/export` → HTML, `/share` → GitHub gist URL ([pi.dev](https://pi.dev), [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)).
- Mario publishes his own real sessions as a Hugging Face dataset and encourages others to do the same (`pi-share-hf`) ([repo README](https://github.com/badlogic/pi-mono)).

**Permissions / sandboxing**
- **None, deliberately**: "Pi does not include a built-in permission system for restricting filesystem, process, network, or credential access. By default, it runs with the permissions of the user and process that launched it" ([repo README](https://github.com/badlogic/pi-mono)). Full YOLO is the only mode.
- Official alternatives: containerization docs with three patterns — Gondolin extension (tools routed into a local Linux micro-VM), plain Docker, OpenShell policy sandbox.
- One real trust boundary: **project trust** — Pi asks before loading project-local `.pi/extensions` / `.agents/skills` (an in-process TS extension can do anything); headless runs default to not loading them ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).

**Extensibility**
- **Extensions**: TypeScript modules loaded via jiti (no build step), in-process, with access to tools, commands, keybindings, events (e.g. `tool_call` hooks that can mutate/block tool input), dynamic context injection before each turn, message-history filtering, custom compaction, custom providers, and the full TUI. Hot-reload via `/reload`; the agent can modify its own extensions in place — "Have Pi manipulate itself in place, hit /reload, and keep going" ([pi.dev](https://pi.dev)).
- **Pi packages**: bundles of extensions + skills + prompts + themes, installed via `pi install npm:@foo/pi-tools` or `pi install git:...`. ~5,400 packages in the registry as of Sept 2026 (per heyuan110; verify). Notably, the most-installed packages rebuild exactly what core refused: `pi-mcp-adapter` (~198k weekly downloads), `pi-subagents` (~66k).
- **No MCP in core** — position, not omission: Playwright MCP = 21 tools / 13.7k tokens dumped into every context; a CLI tool with a README costs zero tokens until read on demand (progressive disclosure, composable via pipes). Steinberger's `mcporter` (MCP-as-CLI) recommended for those who must ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).
- **No sub-agents in core**: "a black box within a black box" with poor context transfer. Prescribed: `pi -p` via bash (Mario's own code-review slash command does this), or tmux-spawned pi for full observability. His deeper argument: mid-session sub-agents for context gathering are "a sign you didn't plan ahead" — gather context in its own session, produce an artifact, start fresh.
- Themes with live reload; custom keybindings.

**Model support**
- 15+ providers, hundreds of models: Anthropic, OpenAI, Google, Azure, Bedrock, Mistral, Groq, Cerebras, xAI, Hugging Face, Kimi, MiniMax, NVIDIA, OpenRouter, Ollama, DeepSeek, Qwen, Z.AI, any OpenAI-compatible endpoint, llama.cpp router for local models. Auth via API keys or subscription OAuth (Claude Pro/Max, ChatGPT Plus/Pro via Codex, GitHub Copilot, xAI).
- **Mid-session model switching** (`/model`, `Ctrl+L`, cycle favorites `Ctrl+P`) with **cross-provider context handoff**: e.g. Anthropic thinking traces become `<thinking>`-tagged text blocks for OpenAI. Custom models/providers via `models.json` or extensions ([pi.dev](https://pi.dev), [origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

**Collaboration/sharing**
- Session export to HTML, gist sharing, HF dataset publishing; full token + cost tracking per message. No multi-user features in core; `pi-chat` (separate repo) covers Slack/chat automation.

## 4. Architecture

- **Language/process**: TypeScript monorepo on Node.js (works on Windows/Linux/macOS, Termux). Single local process; no daemon/server architecture (a deliberate contrast with opencode, whose server model and per-message JSON files Mario criticizes) ([talk summary](https://with-agents.dev/summaries/coding-with-agents/i-hated-every-coding-agent-so-i-built-my-own-mario-zechner-pi/)).
- **Packages** ([repo README](https://github.com/badlogic/pi-mono)):
  - `pi-ai` — unified LLM API. Speaks **four wire protocols** (OpenAI Completions, OpenAI Responses, Anthropic Messages, Google Generative AI) and maps ~30 providers onto them rather than per-vendor clients. Handles provider quirks per-API (e.g. `max_tokens` vs `max_completion_tokens`, `reasoning_content` vs `reasoning` fields). Streaming, TypeBox tool schemas, thinking/reasoning, best-effort token/cost tracking, **abort support through the whole pipeline with partial results returned**. Model registry generated from OpenRouter + models.dev data with typesafe `getModel()`. Works in the browser. Mario rejected the Vercel AI SDK (poor self-hosted/tool-calling support, no real aborts).
  - `pi-agent-core` — agent runtime: tool execution, validation, state, event streaming, message queue (one-at-a-time or all-at-once modes).
  - `pi-tui` — terminal UI library: **retained-mode** component tree (`render(width) → string[]`, optional `handleInput`), caching, and **differential rendering**: compare against a backbuffer, move cursor to first changed line, redraw from there; wrapped in synchronized-output escapes (`CSI ?2026h/l`) for flicker-free atomic updates. **Not** a full-screen/alt-buffer TUI — it appends to native scrollback, preserving the terminal emulator's scrolling, search, and selection.
  - `pi-coding-agent` — the CLI wiring it together (sessions, slash commands, context files, themes) + SDK/RPC/print modes.
  - `pi-telemetry`, `pi-durable`, `chord` — supporting packages (telemetry contracts, durable runtimes, app-composition runtime).
- **Context assembly**: startup = minimal system prompt + tool defs + AGENTS.md chain (+ SYSTEM.md) + skill descriptions; context rebuild is a deterministic walk from current leaf to root of the session tree honoring compaction entries. Extensions can inject/filter per turn.
- **Supply-chain hardening**: pinned exact dep versions, `min-release-age=2`, `save-exact`, npm-shrinkwrap shipped in the CLI package, `--ignore-scripts` installs, lifecycle-script allowlist, pre-commit lockfile guard, scheduled `npm audit` ([repo README](https://github.com/badlogic/pi-mono)).
- **Governance**: issues/PRs from new contributors are **auto-closed by default** and reviewed daily — a deliberate filter against agent-generated slop ("OSS vacations"). Mitchell Hashimoto's Vouch generalizes the idea ([repo README](https://github.com/badlogic/pi-mono), [talk summary](https://with-agents.dev/summaries/coding-with-agents/i-hated-every-coding-agent-so-i-built-my-own-mario-zechner-pi/)).

## 5. Strengths (community-cited)

- **Token efficiency is measurable**: same "PONG" prompt = 1,358 input tokens in Pi vs 31,012 in Claude Code; across three real tasks Claude Code consumed 1.8–2.5× Pi's input tokens, and "four tools were not the bottleneck on any of the three tasks" ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)). Composio's same-model comparison (DeepSeek, 30 tasks): Pi 70% solved / $1.64 vs OpenCode 63% / $2.25, ~1k vs ~6.9k fixed overhead per request ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **Benchmark credibility**: Pi + Claude Opus 4.5 placed near the top of Terminal-Bench 2.0's public leaderboard (5 trials/task, submitted to the official leaderboard) — despite, at the time, having no compaction at all ([origin post](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)).
- **Session tree is the killer feature**: "No other major coding agent ships this, it's the single most underrated Pi feature" — rewind/branch without losing context ([Alex Dunlop](https://www.alexdunlop.com/writing/pi-vs-claude-code-which-ai-coding-agent-in-2026)).
- **Cultural fit for hackers**: "Codex, Claude Code are VS Code, JetBrains. Pi is Neovim"; "Pi is the shape of the thing that should exist"; "I love hacking away at pi extensions" (HN minimalism thread, 551 pts, via [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)).
- **Model freedom**: mid-session switching, subscription OAuth for multiple providers, local models first-class; cheap-provider stacking strategies circulate in the community ([Alex Dunlop](https://www.alexdunlop.com/writing/pi-vs-claude-code-which-ai-coding-agent-in-2026)).
- **Subagentless can be faster/more precise**: "When the main model gives an isolated task to the subagent, the latter goes wild producing a comprehensive report… Without the handoff, the main model does the job much more precisely and conservatively" (HN user, via [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)).
- **Great embeddable substrate**: powers OpenClaw; pi-tui/primitives reused by other agents; Emacs and native macOS clients built on RPC/headless mode ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/), [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)).
- **Self-diagnosing**: "Pi exposes what Claude Code hides… it shows you every inefficiency, every bloated instruction file" — a forcing function for clean context engineering ([Alex Dunlop](https://www.alexdunlop.com/writing/pi-vs-claude-code-which-ai-coding-agent-in-2026)).

## 6. Weaknesses (community-cited)

- **Steep learning curve / you own the orchestration**: no guardrails or scaffolding for big tasks; "you kinda have to wire up the exit conditions yourself since it's so minimal by design" (HN launch thread). New users burn caps fast: one reviewer blew a 4M-token Z.ai cap in an hour after porting a bloated CLAUDE.md ([Alex Dunlop](https://www.alexdunlop.com/writing/pi-vs-claude-code-which-ai-coding-agent-in-2026)).
- **Sandboxing is DIY**: "The biggest issue with Pi is that they don't have proper sandboxing with auto approval. Most solutions are third party and half baked" (HN, via [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)). Bad fit for teams/accountability: "run it in a container" makes the container your CI's and onboarding's problem ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **Extension quality is the Emacs problem**: "For anything you want to build you can ask your agent and it will build it… At the same time half the code is buggy, UI elements will try to overlap one another, and you'll periodically get crashes" (HN, via [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)).
- **TUI strains on big sessions**: scrollback-preserving differential rendering "hogs the CPU as the session gets large, history keeps shifting under your nose" — drove one user to build a native macOS client over headless Pi (Show HN, via [developersdigest](https://www.developersdigest.tech/blog/pi-deep-dive-agent-toolkit-architecture)). Flicker in weaker terminals (VS Code) acknowledged by Mario.
- **"Minimal" is about context, not footprint**: 449 MB npm install (esbuild + provider SDKs), unrequested `fd`/`ripgrep` download on first run, skill auto-discovery silently inflating a 1,358-token request to 10,787 tokens if you have `~/.agents/skills` from other tools ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **The community rebuilds the batteries**: the most-downloaded registry packages are MCP adapters and sub-agents — "either a vindication of primitives or a sign that everyone rebuilds the batteries anyway… I think it's both" ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **Churn & governance friction**: pre-1.0, ~daily releases (pin your version); auto-closed PRs from new contributors alienates some (one HN commenter quit over a brusque interaction, [HN thread reference](https://news.ycombinator.com/item?id=47700972)); `~/.pi/agent` ignoring XDG was the loudest single HN complaint (56 pts, Aug 2026, via [heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **Headless footguns**: `pi -p` hangs when stdin is an open pipe; plain `-p` reports no cost info; provider env-var warning spam ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)).
- **Claude subscription economics are unstable** for third-party harnesses generally (Anthropic blocked, reinstated, then paused metering changes across April–June 2026) — not Pi's fault, but it undercuts the "use your Claude sub in Pi" story; check current terms ([Alex Dunlop](https://www.alexdunlop.com/writing/pi-vs-claude-code-which-ai-coding-agent-in-2026), dated info).

## 7. Distinctive ideas worth borrowing

1. **Session history as a tree in one JSONL file.** Every entry gets `id` + `parentId`; appending a message whose parent isn't the tip creates a branch. Context assembly is a deterministic leaf→root walk honoring compaction entries. Gets you `/tree` navigation, `/fork`, `/clone`, branch summaries of abandoned paths, lossless compaction, and trivial external tooling (parsed with 10 lines of Python) for free. Cheap to implement if the storage format is a tree from day one.
2. **Steer vs follow-up message queues.** Two delivery semantics for mid-run input: deliver-after-current-tool (interrupt) vs deliver-when-idle (queue). One loop-level callback ("after each turn, ask for queued messages") implements both; massively improves the interactivity of long agent runs.
3. **Split tool results: LLM payload vs UI payload.** Tools return text for the model *and* structured `details` for rendering. Kills the parse-the-text-to-render-it problem; lets you truncate the model-facing side without losing UI fidelity.
4. **Progressive disclosure instead of MCP.** Ship capabilities as CLI tools with READMEs the agent reads on demand; token cost paid only when needed, composable via pipes, and the model already knows how to use bash. The system prompt even points the agent at its own documentation so it can self-configure.
5. **In-process TypeScript extensions with no build step (jiti) + `/reload`, so the agent edits its own harness.** Extensions get events (with mutable/blockable tool-call input), tool/command/keybinding registration, per-turn context injection, and full TUI access. "Change the harness, not your workflow" becomes literal: ask the agent to build the feature, reload, continue.
6. **Differential rendering on native scrollback.** Retained-mode components render to line arrays with caching; the renderer diffs against a backbuffer and redraws only from the first changed line, wrapped in synchronized-output escapes. You keep the terminal's native scrollback, search, and mouse selection (which alt-buffer full-screen TUIs sacrifice) while staying flicker-free on modern terminals.
7. **One agent core, four frontends sharing one event stream + session format.** TUI, print/JSON, RPC (strict LF-delimited JSONL for non-Node clients), and SDK all wrap the same `Agent`. Every integration (Emacs mode, CI jobs, chat bots, mobile clients) sees an identical agent — this is what turned Pi into substrate for other products.

## 8. Lessons for a new agent

**Copy**
- **Tiny system prompt + four tools is enough for frontier models.** Measured, benchmarked, and independently reproduced (Composio, heyuan110). Spend your prompt budget on the *user's* context, not on explaining what a coding agent is.
- **Make the session format a documented, boring, parseable tree.** Observability ("see everything the model sees, including injected context") is a feature users emotionally attach to; hidden injection is what drove Pi's creation.
- **Steer/follow-up queues and mid-session model switching** are high-value, low-cost loop features most harnesses lack.
- **Extensions in the host language, in-process, hot-reloadable** beat shell-hook JSON plumbing for power users; ship a package registry early so refusals don't become resentments.
- **Say "no" in the README with the escape hatch attached** ("No X. Do Y instead, or install Z"). Pi's Philosophy section is why its minimalism reads as confidence rather than incompleteness.
- **Provider abstraction by wire protocol** (4 APIs cover ~30 providers) instead of per-vendor clients; aborts and partial results as first-class from day one.
- **Supply-chain hardening matters more when your tool's whole job is executing arbitrary code** — pinned deps, `--ignore-scripts`, min-release-age.

**Avoid / do differently**
- **Don't ship zero guardrails and call it philosophy.** Pi's "permission prompts are theater" argument is right about dialogs but wrong about boundaries — the honest conclusion (OS-level isolation) should be *built in or one command away*, not a docs page. A new agent should ship a default sandbox (seatbelt/bubblewrap/micro-VM) with YOLO as opt-out.
- **Budget for the batteries boomerang.** The most-installed Pi packages are the features core refused (MCP adapter, sub-agents). Either curate/bless canonical community implementations early, or ship minimal versions in core — otherwise quality varies and newcomers get burned.
- **Fix the defaults around auto-discovery.** Silently loading 48 foreign skills (9.4k tokens) contradicts the "nothing hidden" promise; verbose startup reporting of exactly what entered context should be default-on.
- **Plan for scale in the TUI.** Scrollback diffing degrades on huge sessions; consider virtualized history or a hybrid approach before users flee to third-party frontends.
- **Pre-1.0 churn has a cost.** A release a day breaks extensions and workflows — the exact complaint that motivated Pi ("tools change on every release") now applies to Pi itself. Stability channels / LTS would help.
- **Minimalism needs an onboarding story.** Pi converts Claude Code refugees but "has no guardrails to catch" newcomers ([heyuan110](https://www.heyuan110.com/posts/ai/2026-09-06-pi-coding-agent-review/)); a new agent targeting broader adoption needs starter templates and sane defaults layered on the minimal core.
